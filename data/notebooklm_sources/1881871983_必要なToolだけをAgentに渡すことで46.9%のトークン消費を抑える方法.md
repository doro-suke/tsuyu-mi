## 本文
導入
こんにちは、株式会社ナレッジセンスの須藤英寿です。
今回は、コーディングAgentを提供するCursorが実運用で取り入れている、Agentのトークン消費を抑えるための工夫について紹介します。



 サマリー
開発の場面でAgentの利用は進んでいますが、LLMを繰り返し使う都合上、利用にはお金がかかります。特にAgentでの費用がかさむ理由は、LLMは継続して利用する際に、それまでの会話や動作内容を積み重ねてLLMに入力する必要があるためです。
Cursorでは、システムプロンプトの短縮や、Toolの動的読み込みへの対応などを駆使することで最大で46.9%のトークン消費を抑えることに成功しています。
課題意識

 Agentの利用でかかるコスト
Agentは、ひとつの判断や説明をするために、それまでのユーザーの入力やToolの実行結果など多くのデータを入力する必要があります。Agentの利用時のコストを抑えるためには主に二つの観点があります。一つは、可能な限り入力を減らして無駄なやり取りを減らすこと。もう一つは、前半の入力を極力同じ内容にして、キャッシュを利用できるようにすることです。この二つに即する対応をすることで、Agentの費用を抑えることができます。


 手法
Cursorでは、4つの手法を用いて入力されるトークンの量を減らしたり、キャッシュを利用しやすくなるようにしました。

 キャッシュを利用しやすくする工夫

Cursorでは、まずツールの定義やシステムプロンプトを固定して、再利用されるようにしています。
次に、ユーザーのそのセッション内で使う設定を入力します。
そして最後に、実際のやり取りの履歴データを書き込んで、そのセッション固有の情報を追加していきます。
このように、変更頻度の少ない情報を先頭に配置して、変更の多い情報を後半に持ってくることでキャッシュ効率よくAgentを利用できるようにしています。

 入力を短くする工夫
Cursorで取り入れられている、入力そのものを短くするための3つの工夫を紹介します。

 1. システムプロンプトを短くする
システムプロンプトは、Agentの基本的なふるまいを定義する重要な文章です。一方ですべての入力で利用されるため削減による効果は非常に大きいです。
モデルの性能が向上したことによって、細かい指示が不要になり結果的に66%の文章を減らしても同等の性能を維持することに成功しました。

 2. ファイル読み込み時の行番号表示を省略
Cursorでは、ファイルの情報を読み込む際に各行に行番号を入力していました。
これを、10行ごとにすることで1.6%のトークン消費を抑えられるようになりました。
変更前後のイメージ
変更前のファイル内容の渡し方
125 | function foo() {
126 |   const x = ...
127 |   const y = ...
128 |   if (x) {
129 |     ...
130 |   }
131 | }

変更後のファイル内容の渡し方
120 | ...
    | function foo() {
    |   const x = ...
    |   const y = ...
    |   if (x) {
    |     ...
    |   }
130 | ...



 3. ToolやMCPの動的ロード
LLMで何らかの操作を行う、例えばファイルを読み込んだり、編集したりするにはToolやMCPが必要になります。これらは、Agentの中核となる機能である一方で、LLMには常にそれらToolの説明を渡す必要があり、文章量も多くなります。

一方で、作業の中でそのToolが利用されるかどうかは、Toolの種類によって大きな差があります。そこでCursorではRead, Search, Edit, Shellなどの頻繁に利用されるToolはこれまで通りLLMに渡し、それ以外の利用頻度の低いToolはTool名などの最低限の情報のみ渡します。そして利用したいToolがあれば動的に読み込み、利用します。

この工夫によってToolの説明に割いていたトークン数を6割程度削減することに成功しています。
