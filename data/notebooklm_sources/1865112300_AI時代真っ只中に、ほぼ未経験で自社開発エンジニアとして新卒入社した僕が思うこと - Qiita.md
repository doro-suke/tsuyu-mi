## 本文
はじめに
はじめまして。
2026年4月に、社員数150名規模で自社開発とSESの両軸でビジネスを展開している会社へ、自社開発エンジニアとして新卒入社しました。
入社してまだ半年ですが、業務の中でAIの存在があまりにも大きく、日々いろいろなことを考えるようになりました。その考えがまだ新鮮なうちに、どこかにまとめておきたいと思ってこの記事を書いています。

この記事の内容は、入社半年の一個人の完全に主観的な考えです。正解を示すものではなく、「今こう感じている」という記録として読んでいただけると嬉しいです。


自己紹介

建築学生からWebの世界へ
学生時代は建築系を専攻しており、製図や3Dモデリングを使った設計に力を入れていました。
2024年の頭からは、Webサイトの制作・コンサルティングを行う会社でアルバイトを始めました。主な業務は以下のとおりです。

ECサイトのコーディング
Shopify / futureshop を使ったECサイトの構築

ここでHTML・CSS・JavaScriptの基礎を身につけ、独学でReactなども少し触っていました。約2年、AIに頼らず自分の手でコードを書いてきた経験が、今の自分の土台になっています。

現在の業務
入社後は、主に以下のような業務を担当しています。

自社プロダクトの新機能開発
不具合の調査・修正
他部署を交えた仕様の協議

入社半年とは思えないほど裁量のある仕事を任せてもらえていて、とてもありがたく感じています。

2026年新卒は、かなり難しい時代に社会人になったと思う
少し大げさかもしれませんが、僕ら2026年新卒は、なかなか難しいタイミングで社会に出たと感じています。

入社した瞬間から、AIが「当たり前」だった
これまでの新卒は、AIがない状態で基礎を身につけ、そのあとAIという道具を手にする順番でした。
でも僕らは、基礎を固める前から、ほとんど何でもこなせるAIが隣にいる状態でキャリアをスタートしています。便利である一方で、「自分の力」と「AIの力」の境目がとても見えにくい環境です。

「下積み」の仕事がなくなりつつある
かつて新人に任されていたような、小さな修正、簡単な画面の実装、議事録や資料のたたき台づくり。
こうした仕事は、地味だけれど基礎を体に染み込ませるための大事な階段だったはずです。
今はその多くをAIが一瞬でこなしてしまいます。結果として、階段の下の段が抜けたまま、いきなり上の段の仕事を任されているような感覚があります。

期待値だけが先に上がっていく
AIを使えば1年目でも一定の成果が出せてしまうぶん、周囲からの期待値も上がります。
ありがたいことではありますが、「成果が出せること」と「実力があること」がズレたまま評価されていく怖さも感じています。

誰も「正解の育ち方」を知らない
そして一番大きいのは、この状況に対する答えを、まだ誰も持っていないことだと思います。
先輩たちも、AIがある環境で新人がどう育つべきかを経験したことはありません。会社にも、教育の型はまだありません。
つまり僕らは、自分の育ち方そのものを、自分で模索しなければいけない最初の世代なのかもしれません。
大変ではあるけれど、裏を返せば、新しい働き方や学び方を自分たちの手でつくっていける世代でもある。そう前向きに捉えたい気持ちもあります。

チームでのAI活用の現状
私が所属するチームでは、Claude Code を契約して業務に活用しています。
用途は幅広く、コーディングだけでなく資料作成やBacklogの課題整理にも使っています。



用途
内容




コーディング
新機能の実装、不具合修正


設計
実装方針の検討、影響範囲の洗い出し


資料作成
仕様書・説明資料のたたき台


タスク管理
Backlogの課題整理



リポジトリのルールやSkillなど、AIに渡す側の仕組みはある程度整備されています。
一方で、「人間とAIがどう関わって意思決定するか」というプロセスはまだ明文化されていません。AIの使い方は人によってさまざまで、どこまでAIに任せ、どこから人間が判断するかは個人の裁量に委ねられているのが現状です。

感じていること①：自分の思考力が落ちている気がする

「こなせてしまう」ことへの違和感
正直に言うと、今の自分に振られるタスクは、1年目の自分にとって難易度の高いものが多いと感じています。
それでも、AIを使えばこなせてしまうのが現実です。
最近の業務時間の大半は、自分でコードを書くことではなく、Claudeが出した成果物の精査・レビューになっています。最終的な意思決定は自分がしますが、Opus 5世代まで進化したClaudeの成果物は非常に精度が高く、大きく手直しが必要になる場面は多くありません。

「身についた気」になっているだけではないか
資料作成、設計、コーディングと、ほぼすべての工程でClaudeを使っています。膨大な成果物が短時間で返ってくるので、自分の能力が上がったかのように錯覚します。
でも、実際にその力が自分に身についているのかと聞かれると、自信を持ってYESとは言えません。

AIが書いたコードを「読んで理解できた」
自分でゼロから「書ける」

この2つは、似ているようでまったく別物です。読んで納得することと、自分の頭で組み立てることの間には大きな差があり、今の自分は前者ばかりを繰り返しているのではないか、という不安があります。

感じていること②：習熟している分野と、そうでない分野の差

HTML / CSS / JS は「任せても大丈夫」と感じる
約2年、AIなしでがっつり書いてきたHTML・CSS・JavaScriptについては、Claudeに全部書かせても全体を俯瞰して精度の高いレビューができると感じています。

どこが怪しいか、直感的にわかる
「自分ならこう書く」という比較対象が頭の中にある
出力の良し悪しを、自分の基準で判断できる


Java / Vue は「わかるけど、手が追いつかない」
一方で、現在業務で使っているJavaやVueについては状況が違います。
Javaについては、文法やオブジェクト指向の考え方、基本的な標準ライブラリなど、一通りの知識は持っています。コードを読めば何をしているかは理解できますし、AIの出力を追うこと自体に困ることはあまりありません。
ただ、それはあくまで「知識として知っている」レベルです。実際のプロダクトのコードベースで「細かい修正を自力でやって」と言われると、正直まだ手が止まってしまいます。フレームワークの作法や既存コードの設計意図、「この現場ではこう書く」という感覚が、まだ自分の中に積み上がっていないからです。
そのためレビューをしていても、「動いているし、それっぽいからOK」という判断になっていないかと自分を疑う瞬間があります。知識はあっても、良し悪しを見極める判断の基準が、まだできあがっていないのだと思います。

仮説：AIの恩恵は「習熟した分野」でこそ最大化される
この差を経験して、ひとつの仮説を持つようになりました。

AIは、自分がすでに習熟した分野を代替してもらうときに初めて本当の恩恵をもたらす。
未習熟の分野でAIに頼りきるのは、むしろ危険なのではないか。

習熟した分野では、AIは「自分の手を速くする道具」です。
しかし未習熟の分野では、AIが「自分の判断そのもの」を代わりに担ってしまい、自分はその判断が正しいかどうかすら評価できません。
これは、自分がHP制作の現場にいたときの経験とも重なります。
アルバイト時代、ECサイトやLPのコーディングを手で書いていたころは、デザインカンプとブラウザを何度も見比べながら、余白の数px のズレや、スマホで見たときの崩れ、不要に深くなったdivのネストに一つずつ向き合っていました。
その経験があるからこそ、今Claudeが書いたHTML/CSSを見ても、「この余白の取り方だと別の画面幅で崩れそう」「このクラス設計だと後から運用しづらい」といった違和感にすぐ気づけます。道具がAIに変わっても、手で書いてきた中で身についた「サイトをつくる感覚」が生きているのだと思います。
一方でJavaやVueについては、その感覚を持たないまま、いきなり完成品を渡されている状態なのかもしれません。

とはいえ、AIを手放すのは現実的ではない
じゃあ「自己研鑽のためにAIを使わない」という選択ができるかというと、それも違うと思っています。
AIによって生産性は圧倒的に上がっていて、それを手放す判断は、会社としてはNGでしょう。成果を出すことが仕事である以上、ここは避けられないジレンマです。

感じていること③：先輩たちの「自走力」
私の会社では、今年から本格的にClaudeが業務プロセスに導入されました。
AIを使わない時代から開発をしてきた先輩たちを見ていると、自走力の強さを感じます。

前例のない問題でも、自分で当たりをつけて調べ始められる
AIの提案に対して「それは違う」と根拠を持って言える
仕様の曖昧な部分に自分で気づき、関係者に確認できる

これは、AIがない時代に自力で正解を模索していた時間があったからこそ身についた力なのではないかと思います。エラーと何時間も向き合い、ドキュメントを読み漁り、遠回りしながら答えにたどり着いた経験の積み重ねです。
その経験を「ショートカットできてしまう」今の環境で、自分にも同じ力がつくのか。 ここが一番の不安です。

じゃあ、どうするか：今の自分なりの工夫
答えはまだ出ていませんが、今の自分が意識していること・試していることを書いておきます。

1. AIに聞く前に、まず自分の仮説を立てる
いきなりAIに投げるのではなく、「たぶんこう実装する」「原因はここだと思う」と一度自分で考えてから聞くようにしています。
AIの回答と自分の仮説を比べることで、ズレた部分がそのまま学びになります。

2. 「説明できるか」をレビューの基準にする
AIが書いたコードについて、「なぜこの書き方なのか」を他人に説明できるかを自分に問うようにしています。説明できない部分は、理解したつもりになっているだけの部分です。

3. 小さな修正はあえて自力でやる
業務に支障のない範囲で、小さなバグ修正や軽微な改修はAIを使わずに書いてみています。遅くても、自分の手を動かす時間を意識的に残すためです。

4. AIを「答えを出す係」ではなく「先生」として使う
「このコードを書いて」ではなく、「このJavaの仕組みを教えて」「この設計の選択肢とトレードオフは？」と聞くようにすると、同じAIでも得られるものが変わる気がしています。

5. AIの提案を採用しなかった理由を言語化する
AIの提案を却下したとき、その理由をメモしています。「なぜダメなのか」を言葉にできることこそ、判断力の正体なのではないかと思っています。

個人として気をつけていること
ルールが明文化されていないぶん、自分の中では「ここだけは守る」という基準を持つようにしています。その拠り所にしているのが、こちらの記事です。


これからの時代に求められる力は何か
まだ半年の経験ですが、今の時点で「これは大事そうだ」と感じているものを挙げてみます。


問いを立てる力：何を作るべきか、何が本当の課題かを定義する力。AIは与えられた問いには強いが、問いそのものは人間が出す必要がある

評価する力：AIの出力が正しいか、プロダクトやチームにとって適切かを判断する力

ドメイン知識：自社プロダクトや業務、ユーザーへの深い理解。これはAIが持っていない、現場にしかない情報

責任を持つ力：最終的に「これでいく」と決め、その結果に責任を持つこと

人と合意をつくる力：他部署との協議のように、立場の違う人たちと落としどころを見つける力

逆に言えば、「コードを書く」という行為そのものの価値は相対的に下がっていくのかもしれません。ただ、評価する力は、自分で書いた経験の上にしか育たないのではないか、という点が、この記事で一番伝えたかったことです。

画面の外にあるものの価値
少しエンジニアの話から離れますが、最近強く感じていることがあります。

AIが得意なことほど、価値が「安く」なっていく
文章、コード、画像、資料。画面の中で完結するものは、AIによってどんどん速く、安く、大量につくれるようになっています。
それ自体は素晴らしいことですが、誰でも一瞬でつくれるものは、相対的に希少ではなくなっていくとも思います。

だからこそ、オフラインのものに価値が見いだされていく
その反動として、これからはAIが代わりに体験できないものに価値が集まっていくのではないか、と個人的には感じています。


自然：大地を踏みしめること、海の音や匂いを感じること

舞台芸術：その場、その瞬間にしか存在しない演劇やライブ

祝うこと：誕生日や結婚、節目を誰かと一緒に喜び合う時間

文化・歴史：長い時間をかけて人が積み重ねてきた土地や営み

これらはどれも、体と時間を使って、その場にいなければ受け取れないものです。どれだけAIが進化しても、代わりに感じてもらうことはできません。
建築を学んでいたころ、図面や3Dモデルで完璧に見えた空間も、実際に立ってみると光の入り方や音の響き、人の気配でまったく違う印象になることを知りました。身体で感じるものには、画面では伝わらない情報がある。その感覚が、今あらためて大切に思えています。

「愛が目に見える場所」に惹かれる
僕自身、今はIT業界に身を置いています。それでも、舞台や自然、誰かを祝う場のような、オフラインで愛が目に見える場所に強く価値を感じています。
実は学生時代、建築の勉強と並行してダンスの舞台作品づくりをやっていました。仲間と何ヶ月もかけて一つの作品を練り上げて、本番はたった数分。それでも、客席の空気が変わる瞬間や、終わったあとに仲間と顔を見合わせるあの感じは、今でも鮮明に覚えています。あれは画面越しでは絶対に味わえないものでした。
そして今の休日の楽しみは、ロードバイクです。平日はずっとディスプレイとにらめっこしているぶん、休みの日は風を浴びながらひたすらペダルを漕いでいます。坂を登りきったときの景色や、海沿いを走るときの潮の匂いは、どんなに優秀なAIでも代わりに感じてはくれません（Claudeに「今日の海どうだった？」と聞いても困らせるだけですね笑）。
矛盾しているように聞こえるかもしれませんが、僕はそうは思っていません。
AIやテクノロジーが面倒な作業を肩代わりしてくれるなら、そのぶん人間は、画面の外にある大切なものに時間を使えるようになるはずです。そして、そういう時間や場所を守ったり、人と人をつないだりするプロダクトをつくることも、エンジニアにできることのひとつだと思います。
AI時代だからこそ、画面の外で何を大切にするかが、仕事の向き合い方にもつながっていくのではないかと感じています。

おわりに：みなさんに聞いてみたいこと
AI時代に、まさにこれからスキルを身につけようとしているタイミングで社会に出た自分のような人間について、ずっと考えています。

AIがある環境で、僕らの世代はちゃんと能力を高めていけるのか？
どのような学習をすればいいのか？
これからの時代、エンジニアにはどんな能力が求められるのか？
AIが当たり前になった世界で、みなさんは画面の外の何に価値を感じていますか？
