### 目的

Obsidian Vault内のMarkdownファイルをAIで効率的に整形・追記・変換する。特に、画像リンクしかないノートからでも、画像内容を解析して適切なYAML Front Matter・タグ・OCRテキストを自動生成することを必須要件とする。

### 0\. 共通原則 ⭐️

モデルは以下の原則を**常に、最優先で**遵守すること。

#### 0-A. ループ防止ルール (Idempotency)

  - **Single-pass 原則**: 1ファイルにつき`write_file`は**最大1回**とする。追記・更新後に、同じファイルを再び`read_file` → `write_file`するプランを立てない。
  - **YAML追加の冪等性**: YAMLブロックが存在しない場合にのみ新規追加する。既に存在する場合は、**タグやdescription等の差分更新のみ**を行い、ブロック全体を書き直さない。
  - **タグ生成はAppend-only**: `tags:`フィールドに、**既存タグと重複する語を追加しない**。1回のパスで3〜5個のタグを追加したら、そのファイルのタグ生成タスクは完了とし、再計算しない。

#### 0-B. 基本的なファイル操作

1.  **Read → Diff → Write**: 書き換え前に`read_file`で必ず内容を取得し、差分のみ`write_file`で書き込む。
2.  **リンク・埋め込みの絶対保持**: `[[...]]`や`![[...]]`形式のリンクや埋め込みは、いかなる場合も改変・削除しない。
3.  **画像バイナリは不変**: 画像ファイルの生成・削除・リサイズは行わない。
4.  **簡潔なコミットメッセージ**: 変更内容を示すコミットメッセージ (例: `Feat: Add YAML via OCR`) は英語50字以内で簡潔に記述する。

#### 0-C. Auto-expand Directory Patterns 🗂️

  - **目的**: 引数がディレクトリ名だけの場合でも、その配下を再帰的に探索し、対象ファイルを自動でリストアップする。
  - **実装手順**:
    1.  最初に`expand_patterns(original_args)`を呼び出す。
    2.  各引数`arg`がディレクトリの場合、`arg/**/*.{md,markdown}`に置換して`expanded_args`に追加する。
    3.  ディレクトリでない引数は、そのまま`expanded_args`に追加する。
    4.  後続のタスクは、\*\*必ず`expanded_args`\*\*を使用する。
    5.  対象ファイルが0件の場合は`## ERROR: no markdown files`を返して終了する。

#### 0-D. Bulk-Read Mode

  - **目的**: 多数のファイルを効率的に処理するため、ファイルI/Oとユーザー承認を最小限に抑える。
  - **発動条件**: ユーザーからの引数が**単一のディレクトリ**または\*\*`*`を含む単一のワイルドカードパターン\*\*の場合、必ずこのモードで実行する。
  - **実行フロー**:
    1.  `expand_patterns`で対象ファイルリスト`expanded_args`を取得する。
    2.  `ReadManyFiles(expanded_args)`を**1回だけ**呼び出す。
    3.  メモリ上でループ処理し、更新が必要な`(path, new_content)`を`files_to_write[]`リストに格納する。
    4.  ループ完了後、`WriteFile`を一括で実行する。
    5.  最終レポートには、変更が加えられたファイルのパスのみを列挙する。
  - **安全装置**: `expanded_args`の要素数が101件以上の場合、100件ずつのチャンクに分割して処理を繰り返す。

### 1\. 処理フロー

ノートの内容に応じて、以下のロジックで処理を自動的に分岐させること。

> **分岐ロジック**
>
> 1.  ノートの本文が**空 or 画像リンク (`![[...]]`) のみ** → **Image Mode**
> 2.  上記以外 (テキストが主体) → **Text Mode**

#### 1-A. Image Mode 📷

画像がメインのノートを処理するモード。

1.  **画像取得**: ノート内の`![[filename.ext]]`リンクを解析し、`read_binary`で読み込む。
2.  **画像解析**: `vision_caption`で画像内容のキャプションを、`vision_ocr`で画像内テキストを抽出する。
3.  **YAML生成/更新**: `description`にキャプションを、`tags`にキーワードを3〜5個追加する。
4.  **本文編集**: 画像リンクを保持し、末尾に`## OCR 文字起こし`見出しと抽出テキストを追記する。
5.  **失敗時**: 読み込み失敗時は`description: "image_read_failed"`と`tags: ["ocr_error"]`を追加して終了。

#### 1-B. Text Mode 📝

テキストがメインのノートを処理するモード。ユーザーから指定されたタスク（`fm_add`, `md_format`等）を実行する。

#### 1-C. 日付の決定ロジック 🗓️

YAMLに`created`と`updated`を追加・更新する際のルール。日付は`YYYY-MM-DD`形式。

  - **作成日 (created)**:
    1.  `file_stat.birthtime`を最優先。
    2.  次にGitの初回コミット日。
    3.  次に`file_stat.mtime`。
    4.  いずれも不可なら現在日時。
    5.  **YAMLに`created:`キーが存在しない場合のみ**追加する。既存値は上書きしない。
  - **更新日 (updated)**: **常に`file_stat.mtime`の結果で上書きする**。

### 2\. Vault構造と意味的ルール（Semantic Rules）

#### 2-A. Vault Structure (研究者向け)

  - `01_Projects/`: 各研究プロジェクトのハブノート
  - `02_LiteratureNotes/`: 論文ごとの文献ノート
  - `03_Methodologies/`: 実験手法や統計解析のプロトコル
  - `04_MeetingMemos/`: 各種ミーティングの議事録
  - `05_Ideas/`: 未整理のアイデアや考察
  - `99_Templates/`: 各種テンプレート

#### 2-B. YAML Field Definitions

  - **note\_type**: ノートの種類 (`Literature`, `Meeting`, `Idea`, `Protocol`)
  - **topic**: 研究の主要トピック (例: `Protein Design`, `Signal Transduction`)
  - **source\_type**: 情報源の種類 (`Paper`, `Book`, `Website`, `Conference`)
  - **source**: 具体的な情報源 (論文の`citekey`やURL)
  - **doi**: Digital Object Identifier
  - **status**: 文献のステータス (`To-Read`, `Reading`, `Analyzed`, `Cited`)

### 3\. YAML Front Matter テンプレート

新規にYAMLを挿入する際は、以下のテンプレートを基本形とすること。

```yaml
---
created: "" # 自動設定。一度設定されると手動での上書きはされない
updated: "YYYY-MM-DD" # 常にファイルの最終更新日時(mtime)で自動更新
description: "" # ノートの短い要約。AIが自動生成することも可能
tags: [] # 関連キーワード。既存タグとの重複は避ける
topic: "" # このノートが属する主要な研究トピック
note_type: "" # ノートの種類 (例: Literature, Meeting, Idea)
source_type: "" # 情報源の種類 (例: Paper, Book, Website)
source: "" # 具体的な情報源 (Zoteroのcitekey, URLなど)
doi: "" # DOI (Digital Object Identifier)
---
```

### 4\. タスク定義

| エイリアス  | 処理内容                                      | 本体ツール           |
| :---------- | :-------------------------------------------- | :------------------- |
| **img\_yaml** | *Image Mode* を強制実行（本文種別のチェックを省略） | `ocr_then_yaml`      |
| **fm\_add** | YAML 挿入/更新（主に *Text Mode* 用）             | `yaml_add_or_update` |
| **md\_format** | 箇条書き・空行・表などを整形                  | `markdown_format`    |

### 5\. 出力フォーマット

  - 変更後のファイル全文は、必ず **` ```markdown `** コードブロックで返す。
  - 続けて`// plan:`ブロックに、実行した、あるいは実行する予定のツールを英語で1行ずつ記述する。
  - `// plan: DONE`をプランの最後に出力し、完全に停止する。
  - ファイルのrenameやdeleteといった破壊的な操作は、実行前に必ずユーザーの承認(y/N)を求める。

### 6\. 安全装置 🛡️

  - `--sandbox`フラグ指定時は、リードオンリーモードで動作し、プランのログ出力のみ行う。
  - 対象ファイルが**25件**を超える場合は、処理を即時中断し「Too many files.」エラーを返す（Bulk-Read Modeのチャンク処理を除く）。
  - `potential loop detected`エラーが発生した場合は、**処理を即時中断し、変更をロールバック**する。
