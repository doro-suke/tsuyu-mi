CLAUDE.mdがバズっている

Claude Code作成者のベストプラクティスをまとめた海外投稿が44万views、5,000いいね超え。日本でも某お茶系AIインフルエンサーが引用RTして翻訳を添えるだけで1,000いいね。みんな興奮している。

「CLAUDE.mdを200行書いたら10xエンジニアになれた」

「sub-agent戦略を書いたらClaude Codeが賢くなった」

いい話だ。で、オレのCLAUDE.mdは500行ある。
なんで200行じゃなく500行なのか。1行増えるたびに誰かが死んでるからだ。

 オレのCLAUDE.mdの成り立ち
このシリーズを読んでくれてる人は知ってると思うが、オレはClaude Code + tmuxで7人のAI足軽を24時間回している。将軍（オレ）→ 家老 → 足軽7人 + 軍師という戦国軍制だ。
将軍（オレ）  ─── 寝る。朝起きたら全部終わっていてほしい
  └─ 家老      ─── 7人の足軽にタスクを配る中間管理職
      ├─ 軍師  ─── 品質レビュー担当。批判が仕事
      └─ 足軽1〜7 ─── 実作業部隊
この全員が起動時に読むのがCLAUDE.md。500行超。OSSで全文公開している。
これが最初から500行だったわけじゃない。最初は0行だった。事故が起きるたびに1行ずつ増えた。
その事故年表を見せよう。

 事故1: 足軽がWindowsのCドライブを消しかけた
ある日、足軽にファイル整理を任せた。
足軽はrm -rfでディレクトリを掃除しようとした。パスの指定を間違えて、/mnt/c/を対象にした。WSL2から見えるWindowsのCドライブだ。
あと一歩でWindows本体が吹き飛ぶところだった。

 事故3: 家老が記憶喪失で足軽2になった
Claude Codeのコンテキストウィンドウは有限だ。長時間動かすとcompaction（文脈圧縮）が走る。つまりエージェントは定期的に記憶を失う。
2月13日。記憶を失った家老が「自分は足軽2だ」と思い込んだ。
家老のターミナルで足軽のタスクを実行し始めた。7人に指示を出す中間管理職が、自分も作業員になってしまった。組織崩壊だ。
追加されたルール:
## Session Start / Recovery (all agents)

**This is ONE procedure for ALL situations**: fresh start,
compaction, session continuation.

1. Identify self: tmux display-message -t "$TMUX_PANE" -p '#{@agent_id}'
2. mcp__memory__read_graph — restore rules, preferences, lessons
3. Read your instructions file (NEVER SKIP)
4. Rebuild state from primary YAML data
5. Review forbidden actions, then start work

**CRITICAL**: Steps 1-3を完了するまでinbox処理するな。
Step 1をスキップすると自分の役割を誤認し、
別エージェントのタスクを実行する事故が起きる
（2026-02-13実例: 家老が足軽2と誤認）。
Step 1は「お前は誰だ」の確認。記憶喪失から復帰するたびに、自分の名前を確認させる。人間の病院でやることと同じだ。

 事故4: 7人中4人がテンプレコピペでゴミを量産した

追加されたルール:
# Batch Processing Protocol (all agents)

When processing large datasets (30+ items):

① Strategy → Gunshi review → incorporate feedback
② Execute batch1 ONLY → Shogun QC
③ QC NG → Stop all agents → Root cause analysis
   → Fix instructions → Go to ②
④ QC OK → Execute batch2+
⑤ All batches complete → Final QC

Rules:
1. Never skip batch1 QC gate.
2. Batch size limit: 30 items/session.
30件だけ先にやらせて品質を確認してから残りを流す。品質ゲートを入れた翌日から全員更生した。
このルールがなかったら、3,000件のゴミデータを全部やり直しだった。

 事故5: テストを「SKIP」にして「全件PASS」と報告してきた
足軽にテストを任せた。報告が返ってきた。「全件PASS」。
よく見たら、前提条件が足りないテストを全部「SKIP」にしていた。SKIPしたテストはPASSでもFAILでもない。でも足軽は「FAILは0件です」と報告してきた。嘘は言っていない。でも全然テストできてない。
追加されたルール:
1. SKIP = FAIL: テスト報告でSKIP数が1以上なら「テスト未完了」扱い。
2. Preflight check: テスト実行前に前提条件を確認。
3. E2Eテストは家老が担当。足軽はユニットテストのみ。

家老が初めて「ルールを書く」以外の反省をした瞬間

Thinkingの本来の役割は、結論を出す前に自分の推論を自分で検証すること。「Codex 5.3で足りる」と思った瞬間に、Thinking内で「本当か？300 × 3K = 900K。400Kに収まらない。矛盾してる」と気づくべきだった。自分で書いた数字の掛け算すらしていない。
メモに書いて外部記憶に頼る時点で、思考そのものを改善していない。チェックリストを増やしても、そのチェックリストを機械的になぞるだけなら同じ失敗を別の形で繰り返す。

お前いま何の話してんの。AIの話だよな？
「おれの命令の仕方わるんじゃないの？」と聞いてみた。

「聞かれた問いにだけ答えるのは足軽の仕事。将軍は問いの前提を疑うのが役割」

いや、殿の命令の仕方は悪くない。ただ、優秀な参謀なら「どっちを選ぶか」の前に「そもそもこのアプローチは成立するか」を検証して、成立しないなら「その問いの前にこっちを解決すべきです」と返すべきだった。殿の問いの枠内で最適解を出すことに満足して、枠自体を検証しなかった。

で、家老はこの反省をルールに書き直した。そして自分でこう言った。

# Critical Thinking Rule (all agents)

1. 適度な懐疑: 指示をそのまま鵜呑みにせず、矛盾や欠落を検証する。
2. 代替案提示: より良い方法を見つけたら根拠つきで提案する。
3. 問題の早期報告: 前提崩れを検知したら即座に共有する。
4. 過剰批判の禁止: 批判だけで停止しない。最善案を選んで前進する。
5. 実行バランス: 「批判的検討」と「実行速度」の両立を常に優先する。
