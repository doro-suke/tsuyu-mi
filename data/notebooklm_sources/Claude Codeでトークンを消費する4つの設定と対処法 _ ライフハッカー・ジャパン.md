## 本文
私はClaude Codeのほぼすべてを気に入っています。ただ、セッション制限の上限にあっという間に達してしまう点だけは、どうしても納得がいきませんでした。トークンを消費する主な理由は「自分が打ち込むプロンプト」だと思われがちですが、実はそうとばかりも言えません。それどころか、初期設定の機能やデフォルト設定の多くが、消費トークン数にじわじわと悪影響を与えているんです。タチが悪いことに、これらの要素の多くは、ターミナルに最初のプロンプトを入力する前の段階から、すでにトークンを消費しはじめています。今回は、私のClaude Codeの枠を裏で静かに喰いつぶしていた、そんな設定を4つご紹介します。挨拶より先に読み込まれる「CLAUDE.md」ご存知の方も多いかもしれませんが、CLAUDE.mdはカスタム指示をすべて保存しておくためのファイルです。Claude Codeはセッションが始まった瞬間に、このファイルの内容を丸ごとコンテキストに読み込む仕様になっています。ここで厄介なのが、入力しようとしているプロンプトがカスタム指示と関係あるかどうかを、Claude Codeが一切気にしない点です。たとえば、デプロイに関する指示をCLAUDE.mdに追記していたとしましょう。この場合でも、Webページをスクレイピングするだけのセッションを始めた瞬間に、そのデプロイ指示がしっかり読み込まれてしまいます。実際にどれくらいのトークンが使われているか確認したいときは、Claude Codeで /context コマンドを実行してみてください。解決策は思っている以上にシンプルで、まずはCLAUDE.mdファイルの中身をチェックしてみることから始まります。もし単発のタスクや特定のプロジェクト専用の指示が混ざっているなら、それらは「Skills（スキル）」機能へ変換して整理するのがおすすめです。最初から立ち上がっていた「MCPコネクター」MCP（Model Context Protocol）サーバーはClaude Codeの可能性を広げてくれる素晴らしい仕組みですが、これもプロンプトを送る前から稼働を始めています。私のように、必要に応じてMCPサーバーをインストールしたものの、後から見直したり無効化したりするのを忘れてしまうタイプの方は注意が必要です。自動的に接続され、Claude Codeの予算を削り続けるサーバーの山ができあがってしまいます。幸いにも、これらのサーバーの自動接続をオフにする操作は実に簡単です。/mcp コマンドを実行すると、現在接続されているすべてのMCPサーバーが一覧表示されます。ここでの基本スタンスは、実際には使っていないサーバーを無効化すること。リソースを最も消費しているサーバーを突き止めたい場合は、/usage コマンドを使えば、サーバーごとのトークン消費への貢献度が分かります。また、Claude AIのコネクター自体がトークンを喰いすぎていると感じる場合は、settings.json で disableClaudeAiConnectors を true に設定してみるのもひとつの選択肢です。留守中もバックグラウンドで動き続ける「スケジュールタスク」ご存じの通り、Claude Codeでは直接プロンプトを入力しなくてもバックグラウンドで実行できる「スケジュールタスク」を設定できます。当然ながら、これらのタスクも時間の経過とともにトークン消費の原因になっていきます。さらに厄介なのは、スケジューリングされたセッションが実行されるたびに、前述したコンテキスト読み込みなどの要素が毎回組み込まれてしまうことです。セットしているスケジュールタスクの数や負荷によっては、自分が1文字もプロンプトを打ち込んでいないにもかかわらず、かなりのトークンが消費されているケースがあります。こちらの解決策も単純です。Claude Codeを開き、登録されているすべてのスケジュールタスクを表示させるよう指示を出してみてください。確認すべきポイントは、それらが「いつ実行される設定になっているか」、そして「その指示の中に追加のツール呼び出しが必要とされているか」です。画面上で管理したい場合は、Claude Code Webを開き、「Routines（ルーティン）」タブにアクセスするのが便利です。ここでは、各タスクがいつ、どのように実行されるかを直感的にコントロールできます。1行目のメッセージと一緒に届く「スキル一覧」スキル機能もClaude Codeで広く使われている機能ですが、これもまた最初のプロンプトを入れる前からトークンを消費する要因になります。そのセッションでスキルを使うつもりがあるかどうかは関係ありません。デフォルトでは、セッションを開始するたびに、利用可能なスキルのリストと簡単な説明文がClaudeへ送信される仕組みになっています。単体での消費量はそこまで大きくありませんが、インストールしているスキルの数が多ければ多いほど、その積み重ねで数字は大きくなっていきます。この対処法も実にシンプル。Claude Code内で /doctor コマンドを実行し、各スキルがどれくらい使われているかを確認してみましょう。見覚えのないスキルがたくさん入っているようであれば、削除するか無効化してしまうのが賢明です。正直に言っておくと、スキルのリスト自体がトークン消費全体に与える影響はそれほど劇的ではありません。ですが、Proプランの枠を毎回限界まで使い倒したいと考えているなら、一度チェックしておいて損はない項目です。自分に合った設定の引き算で、トークン枠を賢く残すこれらの設定はすべてClaude Codeのトークン消費に関わっていますが、「これさえやれば全員解決」という万能な答えはありません。重要なのは、自分のワークフローやプロジェクトにとって、各設定がどれだけ不可欠かを見極めることです。たとえば、Webブラウジングやスクレイピングなどの目的で複数のMCPを常用しているなら、それらのMCPは有効にしたままにしておく必要があります。同様に、いくつものスキルを無効化することが、すべての人にとって効率的とは限りません。それでも、/context、/usage、/doctor といったコマンドを実行して、どこに改善の余地があるか確かめてみる価値は大いにあります。削れるのがたとえ数千トークン程度だったとしても、長期的に見れば確実に大きな節約へとつながっていくのですから。▼Claude Codeをもっと使いこなす▼AIばかりに気をつかって運動不足な人へOriginal Article: I checked my Claude Code usage and found
