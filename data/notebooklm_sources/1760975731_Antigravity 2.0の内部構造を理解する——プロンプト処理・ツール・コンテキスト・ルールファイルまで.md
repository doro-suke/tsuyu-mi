Antigravity 2.0の内部構造を理解する
Antigravity 2.0はGoogleが提供するエージェント型AIコーディングアシスタントです。単なるチャットボットではなく、ファイル操作・コマンド実行・Web検索・サブエージェント起動などを自律的に行う「エージェント」として動作します。
本記事では以下の観点から、その内部の仕組みを解説します。

 ユーザープロンプトの処理フロー

 1. システムによるコンテキスト組み立て（プログラム処理）
ユーザーがプロンプトを入力すると、まずシステム（プログラム）が以下を組み立てます。

システムプロンプト（Antigravityの動作指示）
ルールファイルの内容（GEMINI.md / AGENTS.md）
会話履歴
環境情報
現在開いているディレクトリ・ファイルの情報

これはLLMは関与しない純粋なプログラム処理です。テンプレート的に情報を束ねてLLMへの入力を構成します。

 2. LLMによる判断（LLM処理）
組み立てたコンテキストをすべてLLMへ渡します。LLMはここで：

次のアクション（ツール呼び出し or 最終回答の生成）を決定する


 3. ツール呼び出しループ（LLM ⇔ システムの往復）
LLMが「ツールを使う」と判断した場合、ツール名と引数を含む命令を出力します。
// LLMが出力するツール呼び出し命令のイメージ
{
  "tool": "grep_search",
  "params": {
    "query": "def main",
    "path": "/project"
  }
}
システムがこの命令を受け取り実際に実行し、その結果をコンテキストに追加して再びLLMへ渡します。LLMはまた判断し——このLLM → ツール実行 → LLMへ戻すのループがエージェントの核心です。
[ユーザー入力]
    ↓
[システム: コンテキスト組み立て]
    ↓
[LLM: 判断・ツール命令生成] ←──────────────┐
    ↓                                    │
[システム: ツール実行]                     │
    ↓                                    │
[ツール結果をコンテキストに追加して再投入]───┘
    ↓（最終回答と判断したら）
[ユーザーへ出力]


 ルールファイルの仕組み
Antigravity 2.0には3種類のルールファイルがあります。

 GEMINI.md — エージェントの「憲法」
LLMへの指示をMarkdownで記述するファイルです。常にコンテキストへ注入されます。

# ~/.gemini/GEMINI.md の例
- すべての回答は日本語で行うこと
- コードコメントも日本語で書くこと
- セキュリティ上の懸念がある変更は必ずユーザーに確認すること


 AGENTS.md — クロスツール共通設定
Cursor・Claude Codeなど複数のAIツールで共有したい規約を書くファイルです。Antigravity固有ではなく、どのツールでも読める汎用的なフォーマットです。


 SKILL.md — オンデマンドで読み込む専門手順書
SKILLについては、Google Antigravity CLI無料枠でSKILLを使ってみた！を参考にしてください。
必要なときだけ読み込まれる専門タスク用の手順書です。

 サブエージェントの仕組み
サブエージェントはツールとして呼び出されるが、内部にLLMループを持つ特殊な存在です。
メインLLM
    ↓「invoke_subagentを呼ぶ」（ツール命令）
システム: invoke_subagentを実行
    ↓
サブエージェント起動（独立したLLMループ）
    ↓
サブエージェントが自律的に作業
    ↓
結果をメインLLMへ返す

 MCP（Model Context Protocol）

 MCPとは
Anthropicが策定した「AIとツールをつなぐ標準規格」です。「AIのためのUSB-C」とも表現されます。

 search_web はMCPか？
答え：MCPではなく、ビルトインツールです。
search_web はAntigravityに組み込まれた標準機能です。ただし、返ってくる「要約」はGoogleのAI（恐らくGoogleのVertex AI Grounding API）が生成しているため、ツール内部にLLMが隠れているという点で他のビルトインツールと異なります。
