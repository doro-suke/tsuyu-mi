## 1. 解決する課題（Problem）
- コードが読めない非エンジニアやPMが、Claude CodeなどのAIエージェントの出力結果やハルシネーション（自信を持った誤り）を正しく検証できず、品質担保やミス防止に苦慮するボトルネックを解決する。

## 2. 実践ルール・判断基準（Actionable Rules）
- **IF** AIに作らせたものが実行可能な成果物である場合 **THEN** 中身のコードを読む前に、必ず自分の手で画面を操作して期待どおりに動くか確認する。
- **IF** AIが「作業完了」と報告した場合 **THEN** 管理画面やファイルなどの実物を直接開き、推測ではなく事実ベースで確認する。
- **IF** AIの出力内容（文章やデータ）を検証する場合 **THEN** 生成した会話とは別の「新しい会話」にそれを貼り付け、根拠の薄い箇所や数字の誤りを指摘させる。

## 3. 避けるべきアンチパターン（Anti-Patterns）
- 1つの同じ会話スレッドのままAIに「自分で書いた内容を確認して」と指示し、前提や思い込みを引き継いだままレビューさせること。
- AIの「すべて公開済みです」「対応できます」といった自己申告を裏付けなしにそのまま鵜呑みにして公開・適用すること。

## 4. 具体的なコード・構成テンプレート（Snippets / Examples）
- 確認プロンプト例（別の会話に貼り付けて実行）:
`次の文章を読んで、根拠が薄い箇所と、数字の誤りを指摘してください。`
