## 本文
私は20年以上デザインに携わってきました。エンタープライズ企業で、個人のデザイナー、デザインマネージャー、開発チームリードとして働いてきました。さまざまなツールが登場しては消えていくのを見てきました。Sketch が Photoshop に取って代わり、Figma が Sketch に取って代わりました。そのたびにツールは変わりましたが、その下にあるプロセスは同じままでした。AI は違います。AI は単にツールを置き換えているのではありません。プロセスそのものを置き換えています。そして多くの人は、その前に何を考えるべきかを考えずに、いきなり楽しい部分、つまりプロンプトを入力してコードが生成されるのを見るところへ飛び込んでいます。それでは、混乱が速くなるだけです。「プロンプトして祈る」ことの問題Claude Code を開きます。「ダッシュボードを作って」と入力します。すると何かが生成されます。見た目は悪くありません。もしかするとかなり印象的に見えるかもしれません。でも自問してみてください。それは正しい問題を解決しているでしょうか？ ユーザーのメンタルモデルに合っているでしょうか？ 情報アーキテクチャの判断は意図的でしょうか、それともランダムでしょうか？ デザイントークンは一貫しているでしょうか、それとも LLM がその場で見栄えのよいものを適当に選んだだけでしょうか？ほとんどの場合、答えは「いいえ」です。出力はソフトウェアのように見えますが、ソフトウェアらしく感じられません。プロトタイプとプロダクトを分ける、目に見えない作業が欠けています。その目に見えない作業こそが、デザインプロセスです。要件整理。デザインブリーフ。情報アーキテクチャ。デザイントークン。タスク分解。レビューサイクル。華やかなものではありません。人々が X に投稿する部分でもありません。しかし、それこそが他のすべてを機能させる部分です。実際のデザインプロセスに従う7つの Claude Code スキルこれに逆らうのではなく、私はそのプロセスを Claude Code 自体に組み込むことにしました。どんなプロジェクトにもインストールして実行できる、7つのカスタムスキルを作りました。曖昧なアイデアから、動作し、アクセシブルで、レビュー済みのフロントエンドへ進む、プロフェッショナルなデザインワークフローに従います。1. Grill Meこれは最も重要なスキルであり、おそらくコード量としては最も短いスキルです。LLM が容赦なくなります。コードが1行も書かれる前に、あなたの要件を徹底的に検証します。質問に答えるだけで20分かかるかもしれません。それが狙いです。何を作るのか、なぜ作るのかを説明できないなら、LLM にそれを作らせるべきではありません。このスキルは、あなたの回答に応じて深掘りする意思決定ツリーを使います。どんな種類のアプリケーションなのか、ユーザーは誰か、規模はどの程度か、エッジケースは何か。出力は、議論した内容をまとめた grill summary です。あなたと LLM の間で交わす要件の握手のようなものだと考えてください。クレジットを明記すると、grill-me のコンセプトは Matt Pocock 氏の github.com/mattpocock/skills にあるスキルの取り組みに着想を得ています。私はそのアイデアを取り入れ、デザイナーのワークフロー向けに適応しました。2. Design Briefgrill が終わると、LLM はデザインブリーフを生成します。ただし、単にあなたの回答を要約するだけではありません。実際のコードベースを確認します。既存のコンポーネント、デザインシステム、リポジトリ内にすでに存在するパターンをチェックします。ブリーフを作成する前に、デザイン固有の質問をします。アプリケーションが何をする必要があるかだけではなく、どのように感じられるべきかを尋ねます。感情的なトーン。視覚的なインスピレーション。ドメインに応じて、Linear や Google Admin Console のような参考例を提案することもあります。デザインブリーフ：IT 資産管理アプリケーション

課題
ノートPC、サーバー、モニター、ライセンス、周辺機器など、50〜500個の資産を管理している 
IT チームは、自分たちが何を所有しているのか、それがどこにあるのか、誰が持っているのか、
保証がいつ切れるのかを明確に把握できていません。スプレッドシートを寄せ集めたり、
雑然としたレガシーツールと格闘したりして、本来なら数秒で終わる作業に時間を浪費しています。

解決策
IT チームが資産インベントリ全体を即座に把握できる、落ち着いて整理されたダッシュボード
アプリケーション。ダッシュボードを一目見るだけで、総数、ステータス内訳、今後の保証期限など、
重要な情報が分かります。資産テーブルでは、管理者がページを離れることなく、すべての項目を
検索、フィルタリング、管理できます。すべてが高速で、スキャンしやすく、多くても2クリック
以内で完了します。

体験原則
密度より明快さ
すべての画面に明確な視覚的階層があります。データは文章の壁ではなく、理解しやすいまとまり
として提示されます。余白は装飾ではなく、構造として機能します。

儀式よりスピード
検索、フィルター、追加、編集などの一般的な操作は、インラインまたはモーダルで行われます。
単純な操作にページ遷移はありません。ユーザーは流れを保ったまま作業できます。
